Local Sandbox Editor — Using Other Repositories

The Local Sandbox Editor can stay inside the developer-sandbox repository while cataloging and previewing projects that live in separate local Git repositories.

1. Start the editor

From the root of developer-sandbox:

npm run editor

Open:

http://localhost:4173

Stop the server by returning to Terminal and pressing:

Control + C

2. Configure another local repository

Edit:

local-editor/editor.config.json

Example:

{
  "port": 4173,
  "databasePath": "data/sandbox.db",
  "projectRoots": {
    "sandbox": ".",
    "modern-agenda": "../modern-agenda",
    "hair-day": "../hairDay"
  }
}

Each name under projectRoots is an alias for a local repository. Paths are resolved relative to the developer-sandbox repository.

3. Reference files from another repo

A configured repo is available through the local editor server at: 

/project-files/ALIAS/

Example image:

<img
  src="/project-files/modern-agenda/assets/screenshot.jpg"
  alt="Modern Agenda screenshot"
>

Example iframe:

<iframe
  src="/project-files/hair-day/index.html"
></iframe>

4. Use a different compatible SQLite database

Change databasePath in editor.config.json. 

{
  "databasePath": "../another-repo/data/projects.db"
}

The other database must use the same tables and columns expected by this editor.

You can also temporarily override the database path when starting the editor:

EDITOR_DB_PATH=/absolute/path/to/projects.db npm run editor

5. Important: local database vs online repositories

The SQLite database works directly with the editor only while the editor is running locally.

Putting sandbox.db in GitHub or another online Git repository does not create a live database server. A normal static website cannot open that repository file with Node's node:sqlite, and it cannot write changes back to the Git repository.

For the public static Sandbox, the recommended workflow is: 

Local Sandbox Editor
        ↓
SQLite database
        ↓
TypeScript export/build step
        ↓
static JSON / generated page data
        ↓
commit + deploy static website

Separate online repositories can consume the exported static data if it is published at a reachable URL. They do not need direct write access to the SQLite file.

6. Recommended repository setup

Developer/
├── developer-sandbox/
│   ├── data/
│   │   └── sandbox.db
│   ├── local-editor/
│   └── ...
│
├── modern-agenda/
│   └── ...
│
├── hairDay/
│   └── ...
│
└── another-project/
    └── ...

Keep each project in its own Git repository. Use the Sandbox editor as the central local catalog, documentation editor, and preview tool. Export the database content for deployment rather than trying to make the public static site write directly to SQLite.
