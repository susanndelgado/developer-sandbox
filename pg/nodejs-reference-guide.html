Node.js at a Glance

Node.js runs JavaScript outside the browser using the V8 engine. It is commonly used for servers, APIs, command-line tools, build tooling, automation, real-time applications, and backend services.

macOS default recommendation: install an LTS Node version through a version manager such as nvm. For production work, stay on an Active or Maintenance LTS line unless a project explicitly requires Current.

Node vs Browser

Node has JavaScript, timers, promises, URL, streams and many Web APIs, but it does not provide browser DOM globals such as document or window.

Node / npm / npx

node runs JavaScript. npm manages packages and project scripts. npx/npm exec runs package-provided command-line tools.

Production Version

As of 2026-08-31: Node 24.20.0 is LTS; Node 26.8.1 is Current. Prefer LTS for ordinary production work.

Project Files

package.json describes the package; package-lock.json locks resolved dependencies; node_modules/ holds installed packages; .nvmrc can pin the project Node version.

Modern Module Default

For new application code, use explicit ESM with "type": "module" and import/export. Keep CommonJS when compatibility requires it.

Fast Dev Loop

nvm use → npm install → node --watch src/app.js → node --test. Put repeatable commands in package.json scripts.

macOS Installation & Version Management

Use one primary installation strategy. Mixing a system installer, Homebrew Node, and a version manager can make which node point to the wrong binary.

The three columns below read as Use / Install / Notes.

nvm — Recommended

Use: best for developers who need to switch Node versions per project. npm's own documentation strongly recommends a Node version manager.

Install:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.6/install.sh | bash
source ~/.zshrc
command -v nvm
nvm install 24
nvm use 24
node -v
npm -v

Notes: macOS uses zsh by default. If ~/.zshrc does not exist, create it with touch ~/.zshrc, then rerun the installer or add the nvm load lines manually.

Official Node Installer

Use: simple single-version setup when you cannot or do not want to use a version manager.

Download: nodejs.org/en/download

Select the LTS release for normal development. Run the macOS installer, then verify:

node -v
npm -v
which node

Notes: npm documentation prefers a version manager because installer-based global packages can lead to permissions problems. Do not use sudo npm install -g as a routine fix.

Homebrew

Use: convenient when you deliberately manage Node through Homebrew rather than nvm.

LTS 24:

brew install node@24
brew info node@24

The unversioned formula currently tracks Node 26:

brew install node

Notes: node@24 is keg-only. Follow Homebrew's displayed PATH instructions if the executable is not found. For projects needing several Node lines, nvm is usually simpler.

Start a Node Project

Left side shows the action; right side shows the implementation or resulting project structure.

1. Create and initialize

Create a clean project directory and a package.json.

mkdir my-node-app
cd my-node-app
git init
npm init -y
2. Pin Node

Add a project Node version file.

echo "24" > .nvmrc
nvm use
3. Use explicit ESM

For a new ESM project, add this to package.json.

{
  "type": "module"
}
4. Add scripts

Put repeatable tasks behind project scripts.

{
  "scripts": {
    "start": "node src/app.js",
    "dev": "node --watch src/app.js",
    "test": "node --test"
  }
}
5. Basic folders

A small service does not need a complex architecture.

my-node-app/
├── src/
│   ├── app.js
│   ├── routes/
│   └── services/
├── test/
├── .env
├── .gitignore
├── .nvmrc
├── package.json
└── package-lock.json
6. Ignore local/generated files

Do not commit dependencies, secrets, logs, or OS metadata.

node_modules/
.env
*.log
.DS_Store
coverage/

package.json Quick Reference

package.json is the project manifest. Node uses some fields directly; npm uses many additional fields.

name / version / private

name identifies the package; version follows semantic versioning. For an application that should never be published accidentally, use "private": true.

{ "name": "my-app", "version": "1.0.0", "private": true }
type

"type": "module" makes nearby .js files ESM. "type": "commonjs" makes them CommonJS. Be explicit.

{ "type": "module" }
scripts

Named development commands run with npm run <name>. start and test also have npm shorthand commands.

{
  "scripts": {
    "start": "node src/app.js",
    "dev": "node --watch src/app.js",
    "test": "node --test"
  }
}
dependencies

Packages required when the application runs.

{ "dependencies": { "express": "^5.0.0" } }
devDependencies

Development-only tools such as linters, test helpers, build tools, or TypeScript tooling.

{ "devDependencies": { "typescript": "^5.9.0" } }
engines

Declare the Node versions the package expects. Enforcement depends on package-manager settings and environment.

{ "engines": { "node": ">=24" } }
main vs exports

main is the older single entry point. For packages, Node recommends modern exports for a deliberate public interface and subpath control.

{
  "exports": {
    ".": "./src/index.js",
    "./utils": "./src/utils.js"
  }
}

Essential Node Commands

These are runtime commands from the Node executable itself.

Run a file

Execute the entry file once.

Example 
node src/app.js
Interactive REPL

Start an interactive JavaScript prompt. Exit with .exit or Control-D.

Example 
node
Evaluate one expression

Useful for quick checks from Terminal.

Example 
node -e "console.log(process.platform)"
Print an expression

-p evaluates and prints the result.

Example 
node -p "process.version"
Syntax check only

Parse a JavaScript file without executing it.

Example 
node --check src/app.js
Watch mode

Restart when the entry point or imported modules change. Watch mode is stable.

Example 
node --watch src/app.js
Watch selected paths

On macOS, explicitly watch directories. This option is supported on macOS and Windows.

Example 
node --watch-path=./src --watch-path=./config src/app.js
Load .env

Load environment variables from a file before the application starts.

Example 
node --env-file=.env src/app.js
Optional .env

Do not fail when the env file is absent.

Example 
node --env-file-if-exists=.env.local src/app.js
Run tests

Use Node's built-in test runner.

Example 
node --test
Open the inspector

Start with the debugger enabled. Chrome DevTools or an IDE can attach.

Example 
node --inspect src/app.js
Break on first line

Pause before application code executes.

Example 
node --inspect-brk src/app.js
Run a package script natively

node --run is a fast, intentionally limited package-script runner. It is not a full replacement for npm lifecycle behavior.

Example 
node --run test
node --run test -- --verbose
Help

List runtime flags available in the installed Node version.

Example 
node --help

Modern Modules: ESM & CommonJS

Node supports both module systems. For new code, explicit ESM is usually the clearest choice. Keep CommonJS where compatibility requires it.

ESM — import / export

Enable with "type": "module", use .mjs, or another explicit ESM marker.

// math.js
export function add(a, b) {
  return a + b;
}

// app.js
import { add } from './math.js';
console.log(add(2, 3));
CommonJS — require

Use .cjs or "type": "commonjs" when you need CommonJS explicitly.

// math.cjs
exports.add = (a, b) => a + b;

// app.cjs
const { add } = require('./math.cjs');
Built-in modules

Use the node: prefix to make it obvious an import is a Node built-in rather than an npm package.

import { readFile } from 'node:fs/promises';
import path from 'node:path';
import process from 'node:process';
ESM file paths

On Node 24, import.meta.dirname and import.meta.filename are stable for local file modules.

console.log(import.meta.dirname);
console.log(import.meta.filename);

const file = new URL('./data.json', import.meta.url);
Dynamic import

Load a module only when needed. import() works in both ESM and CommonJS.

const module = await import('./feature.js');
module.run();
JSON modules

Modern ESM imports JSON with an import attribute.

import config from './config.json' with { type: 'json' };

Core APIs You Reach for Often

Node includes a large standard library. Prefer a built-in API when it cleanly solves the problem; add a package when the ecosystem library provides meaningful value.

File system — promises

Promise-based file access fits naturally with async/await.

Example 
import { readFile, writeFile } from 'node:fs/promises';

const text = await readFile('notes.txt', 'utf8');
await writeFile('copy.txt', text);
Path

Create cross-platform paths rather than manually concatenating slashes.

Example 
import path from 'node:path';

const file = path.join(import.meta.dirname, 'data', 'items.json');
Process

Access environment variables, arguments, platform information, working directory, and exit status.

Example 
import process from 'node:process';

console.log(process.env.NODE_ENV);
console.log(process.argv.slice(2));
console.log(process.cwd());
process.exitCode = 1;
URL

Use the WHATWG URL API for URLs and query parameters.

Example 
const url = new URL('https://example.com/search?q=node');
console.log(url.hostname);
console.log(url.searchParams.get('q'));
Crypto

Use Node's crypto APIs for secure randomness and identifiers.

Example 
import { randomUUID, randomBytes } from 'node:crypto';

console.log(randomUUID());
console.log(randomBytes(16).toString('hex'));
Buffer

Node's binary-data type is common with files, sockets, streams, and encodings.

Example 
const bytes = Buffer.from('hello', 'utf8');
console.log(bytes);
console.log(bytes.toString('base64'));
Events

Many Node APIs build on event-driven patterns.

Example 
import { EventEmitter } from 'node:events';

const bus = new EventEmitter();
bus.on('ready', () => console.log('ready'));
bus.emit('ready');
Streams

Streams avoid loading an entire large input into memory at once.

Example 
import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';

await pipeline(
  createReadStream('large.dat'),
  createWriteStream('copy.dat')
);
Native fetch

Modern Node includes a browser-compatible global fetch(); no request package is needed for ordinary HTTP requests.

Example 
const response = await fetch('https://api.example.com/items');
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const data = await response.json();

HTTP & API Implementation

Node can serve HTTP without a framework. A framework such as Express or Fastify becomes useful when routing, middleware, validation, plugins, or application structure justify the dependency.

Minimal HTTP server

Built-in server with a plain-text response.

Example 
import { createServer } from 'node:http';

const server = createServer((req, res) => {
  res.writeHead(200, { 'content-type': 'text/plain; charset=utf-8' });
  res.end('Hello from Node');
});

server.listen(3000, () => {
  console.log('http://localhost:3000');
});
JSON response

Set the content type explicitly and serialize the object.

Example 
const body = JSON.stringify({ ok: true });
res.writeHead(200, { 'content-type': 'application/json; charset=utf-8' });
res.end(body);
Route by method and pathname

For a tiny service, basic routing can be explicit.

Example 
const url = new URL(req.url, `http://${req.headers.host}`);

if (req.method === 'GET' && url.pathname === '/api/items') {
  // handle request
}
Fetch JSON

Use the built-in global fetch for outbound API calls.

Example 
const res = await fetch('https://api.example.com/items');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const items = await res.json();
POST JSON with fetch

Serialize the body and declare JSON content.

Example 
const res = await fetch('https://api.example.com/items', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ name: 'Bird' })
});
Request timeout

Use AbortController for cancellation and timeout behavior.

Example 
const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 5000);

try {
  const res = await fetch(url, { signal: controller.signal });
} finally {
  clearTimeout(timer);
}
Graceful server shutdown

Stop accepting new connections before the process exits.

Example 
const shutdown = () => {
  server.close((err) => {
    if (err) {
      console.error(err);
      process.exitCode = 1;
    }
  });
};

process.on('SIGINT', shutdown);
process.on('SIGTERM', shutdown);

Environment, Arguments & Process

Keep machine-specific configuration outside source code. Do not commit secrets in .env.

Create .env

Simple key/value configuration. Add the file to .gitignore if it contains secrets.

Example 
PORT=3000
NODE_ENV=development
API_URL=https://api.example.com
Load .env at startup

Node can load env files directly; a dotenv package is not required for this basic use case.

Example 
node --env-file=.env src/app.js
Read environment values

All environment values arrive as strings or undefined; validate and convert them.

Example 
const port = Number(process.env.PORT ?? 3000);
const mode = process.env.NODE_ENV ?? 'development';
Command-line arguments

The first two values are the Node executable and entry file. Application arguments start at index 2.

Example 
const args = process.argv.slice(2);
console.log(args);

// node app.js --verbose
Current working directory

process.cwd() is where the command was launched, not necessarily the module's directory.

Example 
console.log(process.cwd());
console.log(import.meta.dirname);
Exit status

Prefer setting process.exitCode when normal cleanup can finish.

Example 
try {
  await main();
} catch (error) {
  console.error(error);
  process.exitCode = 1;
}

Testing, Watch & Debugging

Node includes a test runner and inspector, so a small project can begin testing and debugging without adding a framework.

Built-in test example

Create a file such as test/math.test.js.

Example 
import test from 'node:test';
import assert from 'node:assert/strict';

function add(a, b) {
  return a + b;
}

test('adds two numbers', () => {
  assert.equal(add(2, 3), 5);
});
Run discovered tests

Run Node's built-in test runner.

Example 
node --test
Watch tests

Rerun tests as related files change.

Example 
node --test --watch
Debug with inspector

Attach Chrome DevTools, VS Code, or another inspector-compatible debugger.

Example 
node --inspect src/app.js
Break before execution

Useful when startup code is the problem.

Example 
node --inspect-brk src/app.js
Timing a code path

Simple built-in timing is useful before reaching for a profiler.

Example 
console.time('load');
await loadData();
console.timeEnd('load');
Trace warnings

Ask Node to show where warnings originate.

Example 
node --trace-warnings src/app.js

Node 24 + TypeScript

Node 24 can execute TypeScript containing erasable type syntax through built-in type stripping. This is useful for lightweight scripts, but it is not a replacement for TypeScript type checking.

Run erasable TypeScript

On current Node 24 LTS, type stripping is stable. Inline types are removed at runtime.

// script.ts
const name: string = 'Node';
console.log(name);

// run
node script.ts
What Node does NOT do

Node's built-in type stripping does not type-check and does not read tsconfig.json.

# still type-check separately
npx tsc --noEmit
Full TypeScript runtime support

For features needing transformation or full tsconfig-aware tooling, use a tool such as tsx.

npm install -D tsx
npx tsx src/app.ts
# or
node --import=tsx src/app.ts
Type imports

When using built-in stripping, use the type keyword for imports that exist only to the type system.

import type { User } from './types.ts';
import { save, type SaveOptions } from './save.ts';
Important limitation

Syntax requiring JavaScript generation—such as some enums, runtime namespaces, and parameter properties—requires transformation rather than simple stripping.

// use full TypeScript tooling when transformed syntax is required

Best Implementation Patterns

These patterns keep Node projects easier to upgrade, debug, deploy, and hand to another developer.

Use an LTS line for production

Pin the intended major/version and upgrade deliberately. Current releases are useful for evaluating upcoming features, not as an automatic production default.

Be explicit about module format

Set "type": "module" or "type": "commonjs". Avoid ambiguous projects that rely on source detection.

Commit the lockfile

Commit package-lock.json for applications so installs are reproducible. Use npm ci in CI when appropriate.

Keep dependencies local

Install project tools in devDependencies and call them through npm scripts or npx. Avoid depending on a globally installed tool version.

Prefer async I/O in servers

Synchronous file and CPU-heavy work blocks the event loop. Use promise/callback APIs for I/O and worker threads or another process for substantial CPU-bound work.

Use built-ins before adding trivial dependencies

Modern Node already includes fetch, test tooling, env-file loading, crypto, streams, URL handling, file APIs, and watch mode. Fewer dependencies can mean a smaller maintenance and security surface.

Validate configuration at startup

Check required environment values once when the application starts. Convert numbers/booleans explicitly and fail with a useful message.

Handle async errors at boundaries

Catch errors where you can log context, return an HTTP response, retry deliberately, or terminate cleanly. Do not silently discard rejected promises.

Separate responsibilities

Keep transport/routing, business logic, persistence, and external-service access separable. This makes tests and replacement easier without forcing a large framework architecture.

Graceful shutdown

Handle SIGINT/SIGTERM, stop accepting new work, close servers/database pools, and allow in-flight work to finish when practical.

Security maintenance

Review dependencies, use supported Node versions, run npm audit, keep secrets out of source control, and review package install scripts when risk warrants it.

Troubleshooting Fast Map

Check the active runtime and project state before reinstalling everything.

node: command not found

Run command -v nvm, which node, and reopen/source your shell config. For nvm on macOS, check ~/.zshrc.

Wrong Node version

Run nvm ls, nvm use, which node, and node -p "process.execPath". A Homebrew or installer binary may be earlier on PATH.

Cannot use import

Add "type": "module", use .mjs, or convert the file to CommonJS. Do not mix module systems accidentally.

require is not defined

The file is running as ESM. Replace require() with import, use .cjs, or deliberately bridge with createRequire().

ERR_MODULE_NOT_FOUND

Check the package is installed, relative ESM imports include the actual file path/extension, and spelling/case matches the filesystem.

EADDRINUSE

Another process already owns the port. On macOS use lsof -i :3000, identify the process, then stop the correct process.

npm EACCES / permission errors

Prefer a version manager so user-owned Node/npm directories are used. Avoid making sudo npm install -g your normal workflow.

Dependencies seem corrupted

For a lockfile-driven clean rebuild: remove node_modules and run npm ci. Do not delete the lockfile unless you intentionally want dependency resolution to change.

Apple Silicon mismatch

Check uname -m, node -p "process.arch", and file "$(which node)". Prefer native arm64 packages on Apple Silicon.

Unexpected working path

process.cwd() follows where the command was launched. Use import.meta.dirname when you mean the current ESM module directory.

Common Workflow Recipes

Short repeatable sequences for the situations you encounter most often.

New project

Create, pin, initialize, and start.

mkdir app && cd app
nvm use 24
npm init -y
mkdir src
touch src/app.js
node src/app.js
Clone existing project

Use the project's Node version and lockfile.

git clone <repo>
cd <repo>
nvm use
npm ci
npm test
npm run dev
Daily development

Run a repeatable dev script rather than remembering long commands.

npm run dev
# usually maps to:
node --watch src/app.js
Before commit

Run the project's checks locally.

npm test
npm run lint --if-present
npm audit
Upgrade Node major

Change runtime deliberately, reinstall, then test.

nvm install 24
nvm use 24
node -v
npm ci
npm test
Find runtime facts

Fast diagnosis for platform and binary mismatches.

node -p "process.version"
node -p "process.platform"
node -p "process.arch"
node -p "process.execPath"
npm -v
