01 — What SQL, PostgreSQL & psql Are

What SQL, PostgreSQL & psql Are

Core Difference

SQL
A language for defining, querying, changing, and controlling relational data.
Used inside psql, applications, GUI clients, migrations, and other database tools.
PostgreSQL
A relational database management system that implements SQL plus PostgreSQL-specific features.
psql connects to a running PostgreSQL server and sends work to it.
psql
A command-line client for PostgreSQL, not a database and not a replacement for SQL.
Accepts SQL plus psql-only backslash meta-commands such as \dt and \d.
What SQL, PostgreSQL & psql Are

Where Code Executes

SELECT * FROM users;
SQL statement interpreted and executed by the PostgreSQL server.
Type it at the psql prompt; psql sends it to PostgreSQL.
CREATE TABLE ...;
SQL data-definition statement executed by PostgreSQL.
psql is only the interactive client carrying the statement.
\dt
Not SQL.
psql meta-command; psql itself uses PostgreSQL metadata to list tables.
\d users
Not SQL.
psql meta-command that describes a relation.
pg_dump
Not SQL.
Separate PostgreSQL client utility for backups; it is not a psql command.
What SQL, PostgreSQL & psql Are

Portable vs PostgreSQL-Specific

Portable SQL
SELECT, INSERT, UPDATE, DELETE, JOIN, GROUP BY, CREATE TABLE, constraints, and transactions are broadly shared across relational databases.
PostgreSQL dialect
Adds PostgreSQL syntax, operators, data types, functions, extensions, and implementation details.
psql layer
Adds interactive conveniences: slash commands, variables, query buffer tools, formatting, scripting, timing, and file execution.
Rule of thumb
If it begins with an unquoted backslash at the psql prompt, it is normally a psql meta-command rather than SQL.
What SQL, PostgreSQL & psql Are

Typical Workflow

1. Connect
Use psql or another client to open a PostgreSQL connection.
2. Inspect
Use psql meta-commands such as \l, \dn, \dt, and \d.
3. Query
Write SQL such as SELECT, JOIN, GROUP BY, INSERT, and UPDATE.
4. Use PostgreSQL features
Apply PostgreSQL types/operators such as JSONB, arrays, RETURNING, ILIKE, or ON CONFLICT when useful.
5. Diagnose
Use EXPLAIN / EXPLAIN ANALYZE and psql timing/output tools.
6. Automate
Move repeatable SQL into migration/query files and run with application tooling or psql -f.

The SQL fundamentals stay recognizable in PostgreSQL; psql supplies the prompt, connection, query buffer, and output controls.

02 — SQL Querying in PostgreSQL

SQL Querying in PostgreSQL

SELECT Anatomy

SELECT columns
Choose result expressions or columns.
Enter normally at the psql prompt.
FROM table
Choose source relations.
Use \dt first when you need to discover tables.
JOIN ... ON ...
Combine related rows.
Use \d table to inspect keys and columns.
WHERE condition
Filter individual rows before grouping.
\p shows the current query buffer before execution.
GROUP BY columns
Group rows for aggregate calculations.
\g sends the current query buffer to the server.
HAVING condition
Filter aggregate groups.
A semicolon normally terminates and sends a complete SQL statement.
ORDER BY expression
Sort result rows.
\pset controls how psql formats returned rows.
LIMIT n OFFSET n
PostgreSQL row-limiting syntax commonly used for pagination.
\timing can show execution duration.
SQL Querying in PostgreSQL

Joins

INNER JOIN
Return matching rows from both sides.
LEFT JOIN
Keep every left row and matching right rows.
RIGHT JOIN
Keep every right row and matching left rows.
FULL OUTER JOIN
Keep matched rows plus unmatched rows from both sides.
CROSS JOIN
Produce the Cartesian product.
SELF JOIN
Join a relation to itself using aliases.
USING (column)
Concise PostgreSQL/SQL join syntax when join-column names match.
Qualified names
Use aliases such as u.id and o.id to avoid ambiguity.
SQL Querying in PostgreSQL

Aggregates & Windows

COUNT(*)
Count rows.
COUNT(DISTINCT id)
Count distinct non-NULL values.
SUM(amount)
Total numeric values.
AVG(amount)
Average non-NULL values.
MIN / MAX
Smallest or largest value.
ROW_NUMBER() OVER (...)
Number rows without collapsing them.
RANK() / DENSE_RANK()
Ranking window functions.
LAG() / LEAD()
Read previous or following row values.
PARTITION BY
Restart a window calculation per group.
SQL Querying in PostgreSQL

Subqueries, CTEs & Sets

WHERE EXISTS (...)
Test whether a subquery returns a row.
WHERE id IN (SELECT ...)
Filter against a subquery result set.
WITH name AS (...)
Create a common table expression for one statement.
WITH RECURSIVE
Express recursive hierarchies and graph/tree traversal.
UNION
Combine compatible result sets and remove duplicates.
UNION ALL
Combine compatible result sets without duplicate removal.
INTERSECT
Rows common to both result sets.
EXCEPT
Rows in the first result but not the second.
SQL Querying in PostgreSQL

NULL & Expressions

IS NULL / IS NOT NULL
Correctly test for NULL.
COALESCE(a,b)
Return the first non-NULL expression.
NULLIF(a,b)
Return NULL when two expressions compare equal.
CASE WHEN ... THEN ... END
Conditional SQL expression.
CAST(value AS type)
Standard-style explicit type conversion.
value::type
PostgreSQL shorthand cast syntax.
CURRENT_DATE
Current SQL date.
CURRENT_TIMESTAMP
Current date and time.
SQL Querying in PostgreSQL

psql Query Buffer

Display the current query buffer.
\g
Send the current query buffer to PostgreSQL.

Send the query and show expanded output where supported.
\r

PostgreSQL speaks SQL, but its dialect includes powerful types, operators, expressions, and data-changing features that are not universally portable.

03 — PostgreSQL Extensions to Everyday SQL

PostgreSQL Extensions to Everyday SQL

PostgreSQL Data Types

BOOLEAN
Native true/false type.
SMALLINT / INTEGER / BIGINT
Signed integer types.
NUMERIC(p,s)
Exact arbitrary-precision numeric values.
TEXT / VARCHAR / CHAR
Character types.
BYTEA
Binary string data.
UUID
Native universally unique identifier type.
JSON / JSONB
JSON text and binary-decomposed JSON storage; JSONB supports indexing and rich operators.
ARRAY
Native arrays of supported element types.
ENUM
User-defined enumerated type.
RANGE / MULTIRANGE
Native range types for values such as numbers and timestamps.
INET / CIDR / MACADDR
Network-address data types.
TIMESTAMP / TIMESTAMPTZ
Timestamp without and with time-zone semantics.
PostgreSQL Extensions to Everyday SQL

Identity & Generated Values

SQL standard identity
GENERATED ... AS IDENTITY is the modern identity-column concept.
PostgreSQL supports identity columns directly.
SERIAL
Not standard SQL; historical PostgreSQL shorthand backed by a sequence.
Still encountered in existing schemas.
nextval(sequence)
PostgreSQL sequence function.
psql \d table exposes default/identity information.
GENERATED ALWAYS AS (...) STORED/VIRTUAL
Generated-column syntax/features are PostgreSQL-version dependent.
Inspect current definition with \d+ table.
PostgreSQL Extensions to Everyday SQL

PostgreSQL Operators

ILIKE
Case-insensitive pattern matching.
~ / ~*
Regular-expression match, case-sensitive / insensitive.
!~ / !~*
Regular-expression non-match.
-> / ->>
Extract JSON/JSONB object/array values as JSON or text.
@>
Containment operator used by types including JSONB and arrays.
<@
Contained-by operator.
&&
Overlap operator for supported types such as arrays/ranges.
||
Concatenate strings and, in PostgreSQL contexts, supported collection-like values.
ANY(array)
Compare against any element of an array.
ALL(array)
Compare against every element of an array.
PostgreSQL Extensions to Everyday SQL

High-Value PostgreSQL Syntax

INSERT ... RETURNING id
Return inserted values without issuing a separate SELECT.
UPDATE ... RETURNING *
Return rows changed by UPDATE.
DELETE ... RETURNING *
Return deleted rows.
INSERT ... ON CONFLICT ...
PostgreSQL upsert / conflict handling.
DISTINCT ON (expr)
PostgreSQL extension for selecting the first row per distinct expression under a defined ORDER BY.
FILTER (WHERE ...)
Apply a condition to an aggregate.
LATERAL
Allow a FROM item/subquery to reference columns from preceding FROM items.
CREATE EXTENSION name
Install an available PostgreSQL extension into the current database.
PostgreSQL Extensions to Everyday SQL

JSONB

payload->'user'
Extract a JSON object value.

Extract a JSON scalar as text.
payload @> '{"active":true}'
Test JSONB containment.
jsonb_build_object(...)
Construct a JSONB object.
jsonb_array_elements(...)
Expand a JSON array into rows.

Common index family for searchable JSONB containment/key workloads.
PostgreSQL Extensions to Everyday SQL

Arrays

ARRAY[1,2,3]
Construct an array.
values[1]
Access an array element; PostgreSQL arrays normally use one-based subscripts.

Return a dimension length.

Expand an array to rows.

Test whether an array contains a matching value.

Array containment test.
PostgreSQL Extensions to Everyday SQL

Schemas & Search Path

schema.table

05 — DDL, DML, Transactions & Security

DDL, DML, Transactions & Security

Create & Change Tables

CREATE TABLE users (...);
SQL DDL creates a table in PostgreSQL.
\d users verifies the resulting definition.
ALTER TABLE users ADD COLUMN ...;
SQL changes table structure.
\d+ users inspects the current structure.
ALTER TABLE ... ADD CONSTRAINT ...;
SQL adds constraints.
\d table shows many constraints and indexes.
DROP TABLE users;
SQL removes a table.
\dt confirms what remains.
CREATE VIEW name AS SELECT ...;
SQL creates a view.
\dv lists views.
CREATE MATERIALIZED VIEW ...;
PostgreSQL creates a stored query result.
\dm lists materialized views.
DDL, DML, Transactions & Security

Constraints

PRIMARY KEY
Uniquely identifies a row.
FOREIGN KEY
Enforces a relationship to referenced rows.
UNIQUE
Prevents duplicate values/combinations.
NOT NULL
Requires a value.
CHECK (...)
Enforces a row-level predicate.
DEFAULT expression
Supplies a value when INSERT omits the column.
EXCLUDE
PostgreSQL constraint preventing rows from matching specified operator combinations.
DEFERRABLE
Allows supported constraint checking to be deferred within a transaction.
DDL, DML, Transactions & Security

Data Changes

INSERT INTO ... VALUES ...
Create rows.
INSERT INTO ... SELECT ...
Insert rows produced by a query.
UPDATE ... SET ... WHERE ...
Change matching rows.
DELETE FROM ... WHERE ...
Delete matching rows.
TRUNCATE table
Quickly remove all rows; PostgreSQL-specific options affect identity/cascading behavior.
RETURNING
Return affected rows from INSERT/UPDATE/DELETE/MERGE-style changes.
ON CONFLICT
Handle unique/exclusion conflicts during INSERT.

Transactions

BEGIN;
Start an explicit SQL transaction.
psql prompt typically changes to indicate transaction state.
COMMIT;
Commit SQL transaction changes.
\echo can annotate scripts around transaction boundaries.

Undo the current transaction.

Create an intermediate rollback point.
Still SQL; psql simply sends it to PostgreSQL.

Useful interactively while testing multi-step changes.
SET TRANSACTION ...;
Choose transaction characteristics.
SHOW transaction_isolation can inspect current settings.

Create a namespace.

Change schema ownership.

\dn+

DDL, DML, Transactions & Security

Prepared SQL from Applications

$1, $2 ...
PostgreSQL server-side positional parameter notation used in prepared statements/protocol contexts.
Client placeholders
Libraries may expose ?, :name, $1, or another API-specific placeholder syntax.
Values vs identifiers
Parameters represent data values, not arbitrary table/column names.
Security rule
Never concatenate untrusted values directly into executable SQL.
psql variables
Useful for scripts, but they are a separate psql interpolation mechanism, not application prepared statements.

PostgreSQL adds implementation-specific performance and administration tools; psql is a convenient place to run and inspect them.

COPY vs \copy

COPY table TO '/server/path/file.csv' CSV HEADER;
SQL COPY reads/writes files from the PostgreSQL server's filesystem and uses server privileges.
\copy table TO 'local.csv' CSV HEADER
COPY table FROM '/server/path/file.csv' CSV HEADER;
Server-side SQL import.
\copy table FROM 'local.csv' CSV HEADER
Privileges
Server COPY can require elevated file privileges.
\copy uses the psql/client machine's filesystem and client access.
Use case
Fast bulk transfer between tables/queries and files.
\copy is usually more convenient from a developer workstation.

Backup & Restore Utilities

Command-line utilities for creating/dropping PostgreSQL databases.

Developer Troubleshooting

Connection refused
Confirm PostgreSQL is running, host/port are correct, and network/firewall rules allow the connection.
password authentication failed
Verify role, password, pg_hba.conf rules, and chosen connection target.
relation does not exist
Check current database, schema, search_path, quoted/case-sensitive identifiers, and object spelling.
permission denied
Check role membership, object privileges, schema USAGE, and ownership.
current transaction is aborted
A statement failed inside a transaction; ROLLBACK or rollback to a savepoint before continuing.
slow query
Inspect EXPLAIN ANALYZE, row estimates, indexes, predicates, join order/strategy, and statistics.
psql aid
\conninfo, \d, \dn, \dt, \timing, \errverbose, and \x are high-value diagnostics.
Indexes, Performance, Maintenance & Tools

Which Tool Should I Use?

SQL
Use when expressing data queries, schema changes, transactions, privileges, and database logic.
Portable concept; PostgreSQL executes its supported SQL dialect.
PostgreSQL feature
Use when PostgreSQL provides a capability valuable to the application, such as JSONB, arrays, RETURNING, extensions, or specialized indexes.
Document dialect dependence when portability matters.
psql
Use for interactive querying, discovery, diagnostics, scripts, formatting, and quick administration.
Do not confuse psql meta-commands with SQL embedded in application code.
PostgreSQL utility
Use pg_dump, pg_restore, createdb, dropdb, vacuumdb, and related tools for their dedicated jobs.
These are separate executables, even though they ship with PostgreSQL client tooling.
