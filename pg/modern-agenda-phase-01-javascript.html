Purpose & Learning Objectives

Why this project exists and what the implementation should teach.
Purpose / Learning

Purpose

Build the framework-free agenda with current JavaScript while treating ES2015 as part of modern ECMAScript.

Learning Objectives

  • Use modern ECMAScript syntax, including important ES2015 foundations and later additions.
  • Organize browser code with ES modules and clear data boundaries.
  • Load agenda JSON with Fetch API and async/await.
  • Render accessible expandable agenda content without a UI framework.
  • Establish the native JavaScript baseline for every later Rosetta comparison.

04

Phase Implementation

Planned behaviors, architecture decisions, and comparison evidence for this phase.
Modern language baseline
Use current JavaScript rather than maintaining separate ES2015 and later ECMAScript builds.
  • ES2015 features remain part of the language baseline.
  • Use later ECMAScript features where they improve clarity.
  • Avoid framework-specific abstractions.
Browser-native architecture
Keep modules, state, rendering, and requests understandable without a framework.
  • Explicit module boundaries.
  • Small rendering functions.
  • Accessible disclosure behavior.
Comparison evidence
Document what later typed and framework phases add beyond native JavaScript.
  • Typing differences.
  • State organization differences.
  • Tooling and build differences.
