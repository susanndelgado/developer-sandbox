Purpose & Learning Objectives

Purpose / Learning

Purpose

Create the clearest browser-native baseline before compiler or framework abstractions are introduced.

Learning Objectives

  • Render structured agenda data with direct DOM APIs.
  • Handle expansion and interaction with browser events.
  • Transform arrays and objects into grouped interface output.
  • Load JSON asynchronously with Fetch API.
  • Separate data transformation from DOM rendering.

Phase Implementation

Data ingestion
Load the common agenda fixture used by every Rosetta phase.
  • Read the shared JSON fixture.
  • Normalize records before rendering.
  • Keep phase data equivalent to later implementations.
Rendering
Build the agenda directly with browser APIs.
  • Create day/session groupings.
  • Render nested agenda details.
  • Avoid framework abstractions in the baseline.
Interaction
Implement expandable content and event handling.
  • Track expanded state.
  • Use accessible controls.
  • Keep behavior comparable with later phases.
Comparison evidence
Document what is explicit in plain JavaScript.
  • DOM work performed manually.
  • State management performed directly.
  • No compiler-enforced types.
