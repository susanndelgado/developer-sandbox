Purpose & Learning Objectives

Why this project exists and what the implementation should teach.
Purpose / Learning

Purpose

Modernize the AngularJS-era agenda with current Angular architecture and TypeScript.

Learning Objectives

  • Break the agenda into focused standalone Angular components.
  • Use TypeScript throughout components, services, and data models.
  • Use services and HttpClient for intentional data access boundaries.
  • Use signals and modern Angular control flow where they fit the problem.
  • Compare current Angular architecture directly with the legacy AngularJS baseline.

Phase Implementation

Planned behaviors, architecture decisions, and comparison evidence for this phase.
Component architecture
Break the agenda into reusable components around real interface and data boundaries.
  • Agenda shell.
  • Day and session groups.
  • Expandable session details.
  • Speaker and moderator presentation.
State and services
Keep shared data access separate from local interaction state.
  • Service-based data access.
  • Signals where useful.
  • Component-local state where appropriate.
Legacy comparison
Document the architectural changes from AngularJS to current Angular.
  • Standalone components.
  • Static typing.
  • Modern templates and control flow.
  • Dependency injection and tooling.
