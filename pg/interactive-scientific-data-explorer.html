02

Purpose & Learning Objectives

Why this lab exists and what the implementation should demonstrate.
Purpose / Learning

Purpose

Create a visual scientific-data exploration interface while sampling modern technologies used in data-heavy frontend engineering.

Learning Objectives

  • Structure a React and TypeScript application.
  • Connect interface state to visual output.
  • Render charts with D3 and SVG.
  • Work with maps and GeoJSON.
  • Understand frontend-to-API data flow.
  • Introduce automated interface testing.
  • Connect development work to containers and deployment.
03

Project Scope

The application grows continuously as each technology adds a visible capability.
Interactive Frontend
Create the application shell and visible interaction model.
  • React component structure.
  • Typed data with TypeScript.
  • Props, state, and events.
  • Search and filtering.
  • Selectable data cards.
  • Responsive detail panel.
Visualization & Mapping
Turn data into coordinated visual interfaces.
  • SVG structure.
  • D3 scales and plotted data.
  • Interactive charts.
  • Leaflet map.
  • GeoJSON features.
  • Selection shared between map, chart, and detail view.
Data & Application Architecture
Move from hard-coded interface data toward application data flow.
  • JSON data structures.
  • Fetch and async/await.
  • Frontend-to-API architecture.
  • Python and Flask orientation.
  • Environment configuration.
  • Separation of client, service, and data responsibilities.
Professional Workflow
Expose the project to testing, containers, deployment, and production concerns.
  • Automated browser testing.
  • Cypress and Playwright concepts.
  • Docker application structure.
  • CI/CD mental model.
  • Cloud deployment architecture.
  • Performance and accessibility checks.

05

Project Notes

Implementation boundaries and technology-selection policy.
Project Notes

Build Approach

Use short visual implementations so each new concept produces an immediate change in the browser. Each addition becomes part of the same evolving application.

Technology Policy

The listed technologies are candidates, not mandatory dependencies. Prefer the smallest useful stack that demonstrates the concept clearly. Advanced infrastructure and 3D technologies remain optional unless the project benefits from them.
